# 英語シャドーイング練習ツール

英文を貼り付けると1文ずつに分割し、「1文再生 → ポーズ（自分が音読）→ 次の文」を
繰り返すブラウザツールです。音声合成は **Kokoro-82M** をブラウザ内で実行するため、
初回のモデル取得が終わればネット接続もAPI課金も不要です。

- 完全オフライン・無料（初回のモデル取得のみ通信が必要）
- 再生速度 0.6〜1.2倍、文間ポーズ 0〜5秒
- 現在の文をハイライト、キーボード操作対応
- 連続再生モード / 1文ずつ手動モード
- `Mr.` `U.S.` `e.g.` などで誤分割しない文分割

## 必要環境

- macOS（Linux / Windows でも動きます）
- Python 3.8 以降（macOS には標準で入っています）
- `curl` と `tar`（macOS 標準）
- Chrome または Safari の新しめのバージョン

Node.js や npm のインストールは不要です。

## セットアップ

```sh
./tools/setup.sh     # モデルと実行環境を vendor/ に取得（初回のみ）
./tools/serve.py     # ブラウザが開きます
```

`setup.sh` が取得するもの:

| 置き場所 | 中身 | 取得元 |
| --- | --- | --- |
| `vendor/lib/` | kokoro-js のブラウザ用バンドル | npm レジストリ |
| `vendor/ort/` | ONNX Runtime の wasm | npm レジストリ |
| `vendor/model/voices/` | 英語音声28種のスタイルベクトル | npm レジストリ |
| `vendor/model/` | Kokoro-82M の重みとトークナイザ | Hugging Face |

### モデルの精度を選ぶ

```sh
./tools/setup.sh --dtype fp32     # 音質優先・WebGPU が使える環境向け
./tools/setup.sh --dtype q8       # 既定。サイズと速度のバランス
```

| dtype | ダウンロード量の目安 | 備考 |
| --- | --- | --- |
| `q8` | 約 90MB | 既定。CPU（wasm）で動かす前提の量子化モデル |
| `fp16` | 約 160MB | 中間 |
| `fp32` | 約 330MB | 最も自然。WebGPU がある環境で有利 |

正確なサイズは `setup.sh` が取得後に表示します。`--dtype fp32` を選ぶと、
WebGPU が使えるブラウザでは自動的に GPU で動きます（量子化モデルは
WebGPU で不安定なため、`q8` のときは CPU を選びます）。
英語以外の音声も入れたい場合は `--all-voices` を付けてください。

## スマホで使う（GitHub Pages）

Kokoro はローカルサーバがないと動かないため、スマホだけで使う場合は
**端末内蔵の英語音声**で動くモードになります。ダウンロードもセットアップも不要で、
文分割・ハイライト・ポーズ・速度・モード切替はすべてそのまま使えます。

公開手順（1回だけ）:

1. GitHub でこのリポジトリを開き **Settings → Pages**
2. **Source** を「Deploy from a branch」にする
3. **Branch** でこのツールのあるブランチと `/ (root)` を選び **Save**
4. 数分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます

iPhone の Safari でそのURLを開き、共有ボタン →「ホーム画面に追加」しておくと
アプリのように起動できます。

スマホ版の挙動:

- 画面は縦向け1カラムになり、入力欄と設定は折りたたまれます
- 再生ボタンが大きくなり、キーボードのショートカット表示は隠れます
- 練習中は画面が消灯しないようにします（Screen Wake Lock 対応ブラウザのみ）
- **iOS では一時停止からの再開時、その文を最初から読み直します。**
  iOS Safari の `speechSynthesis.pause()` は受け付けたふりをして読み続けてしまうため、
  中断して読み直す方式にしています。1文は数秒なので実用上の支障はありません

## 使い方

1. 左側のテキストエリアに英文を貼り付ける
2. **文に分割** を押す（右側に1文ずつ並びます）
3. **再生** を押す

連続再生モードでは、1文読み上げ → 設定した秒数だけ無音（この間に自分が音読）→
次の文、と自動で進みます。手動モードでは1文ごとに止まるので、
`Space` か `→` で自分のペースで進めます。

### キーボード

| キー | 動作 |
| --- | --- |
| `Space` | 一時停止 / 再開（手動モードで停止中は次の文へ） |
| `R` | 今の文をもう一度 |
| `←` / `→` | 前の文 / 次の文 |
| `Esc` | 停止 |

テキストエリアに入力中はショートカットは無効になります。

### 設定

- **再生速度** — 0.6〜1.2倍（0.1刻み）。既定では合成済みの音声を
  ピッチを保ったまま伸縮するので、スライダーを動かすと即座に反映されます。
- **速度をモデル側で再合成** — チェックすると Kokoro に速度を渡して合成し直します。
  抑揚がより自然になりますが、速度を変えるたびに生成が走ります。
- **ポーズ** — 「固定秒数」（0〜5秒）か「音声の長さ×倍率」を選べます。
  長い文ほど音読にも時間がかかるので、倍率指定のほうが実用的なことが多いです。
- **音声** — 英語音声のみを、Kokoro の品質グレード順に並べています。
  選択内容は次回起動時も保持されます。

## 文分割について

ピリオドだけで区切ると `Mr.` `Dr.` `U.S.` `e.g.` `i.e.` などで誤分割するため、
略語を3段階に分けて例外処理しています。

| 段階 | 扱い | 例 |
| --- | --- | --- |
| 常に文末ではない | 直後では絶対に区切らない | `Mr.` `Dr.` `Prof.` `St.` `Fig.` `e.g.` `i.e.` `vs.` 月名・曜日 |
| 文末になりうる | 次の語が大文字なら区切る | `etc.` `Inc.` `Ltd.` `Jr.` `a.m.` `p.m.` `Ph.D.` |
| 頭字語 | 次の語が大文字**かつ**文頭になりうる語なら区切る | `U.S.` `U.K.` `E.U.` `D.C.` `A.D.` |

3段目が2段目と違うのは、`the U.S. Army`（区切らない）と
`moved to the U.S. Then...`（区切る）を見分けるためです。

このほか以下も処理します。

- 引用符・カッコ内のピリオド — `He said, "Go home." Then he left.` は
  閉じ引用符まで含めて1文にします。カッコが閉じるまでは区切りません。
- 小数・URL・メールアドレス — `3.14` `www.example.com` `foo@bar.com`
- イニシャル — `J. R. R. Tolkien`
- 三点リーダ — 後ろが小文字なら区切りません
- 行頭の番号 — `1. Boil water.` は番号ごと1文にします
- 長すぎる文 — Kokoro は約510トークンで打ち切られるため、
  長い文は接続詞やカンマなど節の切れ目で自動的に分けます

**画面から略語を追加できます。** 「文分割の詳細設定」を開いて単語を書き足すと、
その語の直後では区切らなくなります（組み込みの一覧もそこで確認できます）。

### 既知の限界

- 単独の大文字1文字＋ピリオドは常にイニシャル扱いです。
  `The answer is A. Then...` のような文は結合されます。
- 頭字語の判定は文頭になりやすい語の一覧に頼っているため、
  `at 5 p.m. Sarah arrived` のような固有名詞が続く場合は判断を誤ることがあります。

どちらも詳細設定の略語リストか、テキスト側の改行で回避できます。

## オフラインでの動作

`setup.sh` が終われば通信は不要です。ブラウザ側のライブラリは
Hugging Face の URL を直接見に行く作りになっているため、Worker 内で `fetch` を
差し替えて `vendor/` 配下を向けています（`src/tts-worker.js`）。

`tools/serve.py` は単なる静的サーバではなく、次の2つを行います。

- `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy` を付ける
  — これがないと ONNX Runtime がマルチスレッドで動かず、生成が遅くなります
- `.wasm` を `application/wasm`、`.mjs` を JavaScript として返す
  — MIME が違うと wasm のストリーミング読み込みと Worker の import が失敗します

`file://` で `index.html` を直接開くと動きません。必ず `serve.py` 経由で開いてください。

## 音声エンジンの切り替え

設定の「エンジン」で **端末内蔵の音声（Web Speech API）** に切り替えられます。
モデルの取得が終わっていない間、Kokoro の起動に失敗したとき、
GitHub Pages などモデルを置けない場所で開いたときは、自動的にこちらへ切り替わります。

英語音声のみを表示し、macOS / iOS の高品質音声
（Ava, Allison, Samantha, Daniel など、Premium / Enhanced 版を含む）を上位に並べます。
通信が必要な音声（Chrome の Google 系）は別グループにして下に沈めています。

macOS で高品質音声を増やすには、システム設定 → アクセシビリティ →
読み上げコンテンツ → システムの声 → 声を管理 からダウンロードしてください。

## ファイル構成

```
index.html            画面
src/splitter.js       文分割（DOM 非依存・単体テストあり）

src/tts-worker.js     Kokoro 推論ワーカー
src/app.js            再生制御と UI
src/style.css

tests/splitter.test.mjs
vendor/               setup.sh が作る（git 管理外）
```


## トラブルシューティング

**「モデルファイルが見つかりません」と出る**
`setup.sh` が最後まで完了していません。もう一度実行してください
（取得済みのファイルは飛ばすので最初からやり直しにはなりません）。

**生成が遅い**
`--dtype fp32` で取り直すと WebGPU が使われて速くなります。
また `serve.py --no-isolation` を付けていると wasm が単スレッドになります。

**途中で止まる／音が出ない**
ブラウザのタブを再読み込みしてください。
それでも直らない場合は `vendor/` を消して `setup.sh` からやり直してください。
